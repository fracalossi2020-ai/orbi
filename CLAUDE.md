# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Orbi (package name `prumo`, some strings still say "prumo") is a ride-hailing platform in one Next.js app: marketing site, passenger app, driver app and admin panel sharing one database. UI text, comments and docs are in Brazilian Portuguese; keep that. See `README.md` for product decisions and the pre-launch checklist.

## Next.js version warning

`AGENTS.md` says this Next.js (16.x) differs from older versions. Read the relevant guide in `node_modules/next/dist/docs/` before touching Next APIs. Notably, `src/proxy.ts` is the middleware (renamed): it sets a per-request CSP nonce, so inline scripts must go through Next's nonce handling.

## Commands

```bash
npm run dev                 # http://localhost:3000 (embedded PGlite DB in .data/, created automatically)
npm run typecheck           # tsc --noEmit (there is no lint script)
npm test                    # vitest: pure rules in tests/**/*.test.ts (via scripts/test.mjs, see gotchas)
npm test -- tests/pix.test.ts               # one test file
npm test -- -t "name fragment"              # one test by name
npx next build && npm run test:e2e          # Playwright, real browser, throwaway DB
npx playwright test e2e/rules.spec.ts       # one e2e file (still needs a prior `next build`)
npm run admin:create -- "Name" email@x.com admin   # prints the password once
npm run db:generate         # drizzle-kit migration from src/database/schema.ts
npm run celular             # Cloudflare tunnel + QR code to test on a phone (real https, so GPS works)
node scripts/build-pages.mjs orbi   # static showcase for GitHub Pages into out/ (base path /orbi)
```

## Running gotchas

- **Embedded DB takes one process.** Stop the dev/prod server before `admin:create`. Do not run `next build` while `next dev` is running (they share `.next`).
- **`next start` refuses the embedded DB.** Without `DATABASE_URL`, production mode throws and the public APIs (`/api/public/*`) return 500, which silently empties city lists and pulse. To run production mode locally: `PRUMO_ALLOW_EMBEDDED_DB=true AUTH_SECRET="$(cat .data/secret)" npx next start -p 3000`. A 200 on `/` proves nothing; check `/api/public/pulse` too.
- **Três hosts (opcional, desligado por padrão).** Só liga com `SITE_URL`, `APP_URL` e `ADMIN_URL` (https, três hosts diferentes; regras puras em `src/shared/hosts.ts`, testes em `tests/hosts.test.ts`). `src/proxy.ts` (agora inclui `/api` no matcher) decide por host: desconhecido 421, API/`/admin` no host errado 404, páginas redirecionam para o host da configuração (nunca do Host do pedido); `x-forwarded-host` só com `TRUST_PROXY=true`. Sessão: `__Host-orbi_session` (app) e `__Host-orbi_admin` (admin), claim `scp` no JWT, `readSession` só lê o cookie e o escopo do host atual; o www nunca tem sessão (`siteUser()` no lugar de `currentUser()` nas páginas do site). App recusa conta da equipe, admin recusa quem não é equipe (mensagem genérica); o admin tem login próprio (`AdminLogin` dentro de `src/app/admin/layout.tsx`). `sameOrigin` no modo separado aceita só o Origin do próprio host. Redirects entre hosts usam `linkTo()` (`src/backend/host.ts`). Para testar: `*.localhost` no Chrome; e2e em `e2e/hosts.spec.ts` (servidor da porta 3103, `scripts/e2e-hosts-server.ts`; o Node não resolve `*.localhost`, então as chamadas de API usam o cabeçalho Host). Sem `SITE_URL`/`ADMIN_URL` nada disso muda: um host só, cookie `prumo_session`.
- **E2E uses port 3100** and `.data-e2e/` (wiped each run, started by `scripts/e2e-server.ts` with a fake OIDC server). It never touches `.data/`. `workers: 1`; tests share state.
- **Run vitest through `npm test`, not `npx vitest`.** When VS Code opens the project the cwd has a lowercase drive letter (`c:...`); vitest then loads modules twice and every suite fails with `Cannot read properties of undefined (reading 'config')`. `scripts/test.mjs` re-launches it from the uppercase path.
- Port 3000 may already be taken by an unrelated local program (a Remotion Studio showed up once). Check what answers before assuming it is Orbi.
- **GitHub Pages showcase** (`.github/workflows/pages.yml`, runs on every push to main): `NEXT_PUBLIC_STATIC=1` + `output: "export"`. `scripts/build-pages.mjs` moves the apps, admin, API, `(auth)` and `proxy.ts` aside (restored afterwards locally, deleted in CI), writes "app em breve" pages for `/entrar` and `/cadastro`, and builds with an in-memory seeded DB (`PRUMO_DB_MEMORY=1`). In the browser, `api()`/`usePublic` answer from `src/frontend/lib/static-api.ts` (Photon/OSRM/Nominatim called directly, tariffs from `/data/tariffs.json`). Raw URLs (fetch, `window.location`, public assets) must go through `asset()` from `src/frontend/lib/site-mode.ts` to get the base path; `<Link>` gets it automatically. The build still writes `.next`: stop the local server first and run a normal `next build` afterwards.
- `.data/` (DB, uploads, `secret`) and `.env*` are gitignored; keep it that way.

## Architecture

Folders: `src/backend` (server engine), `src/database` (Drizzle), `src/shared` (pure rules used by both sides), `src/frontend` (`components/` + client `lib/`). `src/app/` (pages + REST routes) and `src/proxy.ts` must stay where they are: Next.js only finds routes there. Aliases follow the folders: `@/backend/…`, `@/database`, `@/shared/…`, `@/frontend/components/…`, `@/frontend/lib/…`.

Layering, from pure to impure:

- `src/shared/`: pure rules with no I/O (pricing/commission, dispatch scoring, ride state transitions, permissions, Pix, CPF/CNH/CNPJ/plate validation). Everything unit-tested in `tests/`. Business logic belongs here, not in route handlers.
- `src/backend/`: the impure engine. `rides.ts` runs the ride lifecycle on top of `shared/transitions` and `shared/dispatch`; `auth.ts` (sessions via `jose`, login rate limit), `bus.ts` (real-time events to clients over SSE at `/api/events`), `payments.ts`, `geo.ts` (OSRM/Photon/OpenFreeMap calls), `verify.ts` (email DNS, ViaCEP), `guard.ts`/`security.ts`, `admin-resources.ts` (generic CRUD config behind `/api/admin/r/[resource]`).
- `src/database/`: Drizzle schema, SQL migrations (generated, do not hand-edit), `seed.ts`. `src/database/index.ts` chooses PostgreSQL (`DATABASE_URL`) or embedded PGlite. The seed creates only cities, modalities, categories and tariffs; never invent drivers, rides or payments.
- `src/app/api/`: REST routes, thin wrappers over `src/backend`. Catch-all segments (`[...path]`, `[[...action]]`) are used heavily, so grep for the route file rather than guessing paths.
- UI: `src/app/(site)/` marketing pages, `(auth)/` single entry (phone decides login vs signup), `passageiro/`, `motorista/`, `admin/` apps, `v/[token]` shared-trip page. Shared pieces in `src/frontend/components/` (`components/site/` for the marketing site, `components/app/` for the apps).

Business rules that span files (do not hardcode elsewhere):
- Commission is never fixed in code: it lives on each tariff (city + category) and an active plan can override it. Commission applies to gross only; coupons are paid by Orbi and do not reduce the driver's net; the service fee (`tariffs.service_fee_cents`, paid by the passenger when above 0) still exists in the tariff and in pricing, but at launch it is R$ 0 (owner decision, 21/11/2026): Orbi's revenue is only the 15% commission, and the UI hides the fee line when it is 0. The seed only creates tariffs, so existing databases are zeroed with `scripts/zero-service-fee.ts`. Cash rides put Orbi's share as a debit on the driver's balance (it can go negative).
- Clube Orbi (`src/shared/plans.ts`): no lançamento só o nível grátis (`FREE_TIER`, sem cobrança, desconto vem da oficina parceira). Não existe Básico pago. Plus (R$ 129, 14%) e Pro (R$ 289, 13%) ficam com `plans.active = false` (a UI mostra "em breve", `subscribePlan` responde 409 via `planSubscribeError`) até existirem crédito mensal, guincho e o código/QR da oficina. Bancos antigos: `npx tsx scripts/clube-gratis.ts` (idempotente, não apaga linhas).
- Dívida do motorista (`src/shared/debt.ts`, `src/backend/debt.ts`): saldo <= -limite (setting `debt.limitCents`, padrão R$ 150) bloqueia ficar online (409 "Quite o saldo com a Orbi para voltar a dirigir") e tira o motorista do dispatch (`buildCandidates`); a partir de 70% só avisa; corrida em andamento termina. Quitação manual: chave Pix da Orbi na setting `orbiPix`, pedido "Já paguei" em `debt_settlements` (1 pendente por motorista, `POST /api/driver/settlements`), e `POST /api/admin/settlements/:id` (permissão `payments` write, recusa exige motivo) confirma lançando `ledger.type = debt_settlement`. Nunca crie crédito sem a confirmação da equipe.
- Dispatch scores each criterion 0..1 with weights editable in `/admin/configuracoes`; new drivers get neutral values.
- Sign-up always creates a passenger and requires a CPF (`users.cpf`, unique; lookups that reveal a CPF are rate-limited). Becoming a driver happens only afterwards via `/passageiro/dirigir` → `POST /api/account/become-driver`; a driver keeps using the passenger app, but cannot request a ride while online or on a ride as driver, and dispatch never offers a ride to its own passenger. The app entry (`/entrar`) is a direct login screen (phone or e-mail + password, "Lembrar de mim" = session cookie when unchecked), but a device that never signed in (`localStorage` `orbi-conta`, see `src/frontend/lib/visitor.ts`) opens on "Crie sua conta" instead; `?etapa=login` forces the login, `?etapa=cadastro` (what `/cadastro` redirects to) the sign-up, `?etapa=celular|email` the phone/e-mail step (e2e `chooseEntry` uses these); `AppSplash` plays on every app open (~2.5 s: two quick hops, then a fast orbit spin and zoom that fills the screen into the login; wordmark in Outfit 800), but not after in-app redirects (callers use `skipNextSplash()` from `src/frontend/lib/splash.ts`; a nonce'd head script hides it before paint) nor under automation (`navigator.webdriver`, so e2e stays fast). The PWA `start_url` is `/entrar`.
- A ride needs a driver whose documents, vehicle and registration are approved in `/admin/motoristas`. "Test mode" (manual map location) exists only outside production.
- Corridas presas e revisão: a equipe encerra (cobra o estimado ou um valor, até 3x) ou cancela uma corrida aberta em `/admin/viagens` (`POST /api/admin/rides/:id/close|cancel`, motivo obrigatório, admin e gestor). O motorista pode encerrar a mais de 500 m do destino com um motivo: cobra o trecho feito e marca `rides.review_reason` + auditoria `ride.review_flag`. O sweeper marca "para revisão" (uma vez, avisa a equipe) a corrida em viagem há mais de 3x `durationS` (mínimo 60 min), sem encerrar sozinho. Regras puras em `src/shared/ride-resolution.ts`.
- SOS (`src/shared/emergency.ts`, `src/backend/emergency.ts`): só em corrida `accepted/arrived/in_progress` ou até 30 min após `completed` (senão 409); no máximo 1 alerta aberto por corrida (novo acionamento só atualiza posição, hora e `trigger_count`, sem novo e-mail); 3 alertas novos por hora por pessoa; o 4º alerta novo na hora é registrado mesmo assim (auditoria `throttled:true`, aviso à equipe, sem e-mail/webhook) e a resposta traz `message`. Links do e-mail vêm de `APP_URL` (obrigatória e https em produção de verdade; sem ela, só `http://localhost:3000` fora de produção). Webhook opcional (`EMERGENCY_WEBHOOK_URL`, https) vai assinado em `X-Orbi-Signature` e exige `EMERGENCY_WEBHOOK_SECRET` (sem fallback no `AUTH_SECRET`). O cursor de paginação das listas é `<ISO>|<id>`; `review_reason` só aparece para a equipe.
- Orbi Moto: a moto NÃO entra no lançamento (uns 60 a 120 dias depois, piloto em Ipatinga, sem data prometida): a modalidade `corrida-moto` fica desligada. O aviso "Orbi Moto: em breve" é o componente `src/frontend/components/MotoSoon.tsx` (texto e requisitos em `src/shared/moto-soon.ts`). "Quero ser avisado" chama `POST /api/public/moto-interest` (limite de 10/h por IP): logado, usa nome, e-mail e telefone da conta sem corpo; anônimo, pede nome, e-mail e consentimento. Grava em `leads` com `kind = "moto"` (sem migração), um por e-mail. O atalho Moto do passageiro considera a cidade da partida/GPS quando conhecida (`motoOfferedAt`).
- Orbi Food (DEMONSTRAÇÃO, sem banco e sem API de escrita): só existe com `PRUMO_FOOD_DEMO=true` no servidor (lido em runtime por `src/backend/food.ts`; desligado, tudo dá 404; `runtimeConfigProblems` não recusa, e por isso a faixa "DEMONSTRAÇÃO · dados fictícios" aparece no /loja, no /admin/food e em /food-logo; a aba do passageiro (/passageiro/food/**) NÃO mostra faixa nem selos de demonstração, então a demo nunca deve ser ligada em produção pública com as lojas fictícias; fotos genéricas em `public/food/` (Wikimedia Commons, créditos em `src/shared/food/photos.ts` e na página /creditos)). Dados fictícios em `src/shared/food/demo-data.ts` (7 lojas, comissão 14% tudo incluído na entrega própria, entrega Orbi "em breve" sem número), regras puras em `src/shared/food/` (`pricing`, `order-state`, `hours`, `commission` com `effectiveCostBps`/`priceBelowCompetitor`, `calculator` com a referência de mercado de nov/2026; testes `tests/food-*.test.ts`). Carrinho, pedidos simulados e ajustes do painel ficam no `localStorage` (`src/frontend/lib/food-storage.ts`). Telas: aba Food do passageiro (`/passageiro/food/...`), painel da loja `/loja` (host do app, qualquer logado), `/admin/food` (permissão `food`, só leitura), logos em `/food-logo` (`OrbiFoodLogo.tsx`) e "Quero minha loja" em `POST /api/public/food-interest` (leads `kind = "food"`). Fora da vitrine do Pages (`build-pages.mjs`). e2e em `e2e/food.spec.ts` (o 404 sem o interruptor é conferido no servidor 3103, que não liga a demo).
- Notas: a avaliação do motorista fica em `drivers.rating_sum/rating_count`; a do passageiro em `users`. Exclusão de conta é uma transação, bloqueada com saldo diferente de zero ou saque `requested`; bloqueada também com pagamento Pix `pending` no provedor (passageiro ou motorista da corrida, 409). Quem foi motorista com histórico REAL de motorista (corridas concluídas dirigindo ou lançamentos de saldo; corridas como passageiro não contam) deixa o HMAC do CPF (`deleted_cpf_blocks`, 180 dias). O bloqueio vale só para virar motorista de novo (`cpfDriverBlocked` em `become-driver` e no onboarding de motorista); `cpfTaken` e o cadastro de passageiro não o consideram. Admin libera em `POST /api/admin/cpf-block-release` (só role admin, motivo obrigatório, auditoria `user.cpf_block_release`; UI em /admin/usuarios). Regras puras em `src/shared/account-deletion.ts`.
- Listas de corridas (`GET /api/rides`, `/api/driver/history`, `/api/admin/rides`) usam `rideSummaries` (vista enxuta, em lote, paginada por `limit`/`before`); só a corrida ativa usa `rideView`. "Hoje/semana/mês" e os dias dos relatórios seguem o horário de Brasília (`src/backend/sql-time.ts`).
- Acesso (etapa 1 do endurecimento): tentativas de autenticação usam `rateLimitDb` (`src/backend/rate-limit-db.ts`, tabela `rate_limits`); o resto segue em memória. Bloqueio de conta em `src/shared/lockout.ts` + `src/backend/login-guard.ts` (`users.failed_logins/locked_until`; conta bloqueada recebe o 401 genérico sem checar a senha; `PRUMO_LOGIN_DELAY_SCALE=0` só no e2e, recusada em produção). Painel: `requireStepUp(session)` nas ações de `src/shared/step-up.ts` (`POST /api/account/step-up`, modal em `StepUpModal`, senha como alternativa só sem `PRUMO_REQUIRE_STAFF_MFA`); conta da equipe nasce por convite (`staff_invites`, `/convite/[token]`, `src/backend/invites.ts`), nunca com senha escolhida por quem cria; `ADMIN_ALLOWED_IPS` (`src/shared/ip-allow.ts`) vale no proxy, em `route()` e no layout; sessões: equipe 3 e 30 min parada, demais 10 (`src/shared/sessions.ts`); `audit_log` e `sessions` guardam IP mascarado. No e2e, `adminApi()` divide uma sessão só e já faz o step-up; contas da equipe de teste vêm de `createStaffApi`.
- Acesso (etapa 2): robôs em `src/shared/bot-guard.ts` + `src/backend/bot-guard.ts` (campo `website` e carimbo via `useBotGuard()` de `BotGuard.tsx`; tetos diários `DAILY_CAPS`; `PRUMO_FORM_GUARD_RELAX` só no e2e). `reset-request` sempre responde igual; `lookup` limitado por identificador (`identifierHash`) e global. `tariffs` e `plans`: só admin escreve. CPF/CNH mascarados para o atendente (`staffUserView(u, canSeeFullPii(role))`, revelar em `POST /api/admin/pii/:id`). Export da conta é `POST /api/me/export` com `requireReauth`.
- `bus.ts` and the login rate limit are in-memory: single-instance only until moved to Redis.

Visual identity: `src/frontend/lib/identities.ts` + CSS variables in `src/app/globals.css` define four brand identities (A is the shipped Orbi one: electric blue, Inter, cyan→blue gradient `--grad`). Dark sections use `.on-deep`/`bg-deep`.

Maps are MapLibre loaded lazily (`frontend/components/LazyMap.tsx`, `MapView.tsx`). The driver section of the site animates an offer on a light phone (`OfferFlow.tsx`, only while on screen). There is no 3D/WebGL on the site anymore. The marketing site (`(site)` layout, class `.site-one` in `globals.css`) ignores the app theme: white base, black text, Electric Blue accents, no theme toggle. Every `section.on-deep` inside it becomes a rounded inset panel (black by default, `.panel-blue` for blue); `.hero-light` flips a section's deep tokens to white (home hero, `PageHead`). No glows, dot grids or coloured shadows. The home is three parts: hero + `ConceptStrip` (what it is), `FinalCta` + `DriverBand` (go to the app), `HomeFaq` (FAQ + social links from `src/frontend/lib/social.ts`). The hero phone (`LiveTrip.tsx`) simulates a requested ride arriving.
